Project 1: Enriching Sandro Botticelli's Primavera within the ArCo Knowledge Graph

Project Abstract

This project explores the collaborative enrichment of cultural heritage metadata through the combined use of Knowledge Graphs (KGs) and Large Language Models (LLMs) within the ArCo framework. Focusing strictly on Sandro Botticelli's *Primavera* (c. 1482), we execute specialized SPARQL queries to audit data deficiencies in online digital registries. By leveraging zero-shot, few-shot, and chain-of-thought prompt engineering, we generate new validated semantic triples to model individual canvas components, bypassing narrative constraints to capture fine-grained spatial and situational realities.

1. Semantic Gap Identification

The institutional cultural registry records for Botticelli's Primavera within public endpoints model the painting exclusively as a single, monolithic entity (arco:CulturalProperty). Our audit reveals a clear **knowledge gap**: the nine independent mythological figures interacting across the canvas (Mercury, the Three Graces, Venus, Cupid, Flora, Chloris, and Zephyrus) completely lack individual semantic bounds, spatial localization properties, or unique identifiers.

Because individual compositional components (arco-cd:CulturalPropertyComponent) are unindexed, semantic search agents cannot query or compute relational pathways between the characters. Resolving this spatial and thematic data gap is the primary focus of this enrichment project.

Compositional Blank Space Individual actors possess no URI strings within the graph, preventing granular metadata retrieval.
Spatial Overlap Failures Intricate groupings (such as the interlocking fingers of the Three Graces) lack distinct spatial coordinate delimiters.
Transformation Representation The mythological sequence where Zephyrus transforms Chloris into Flora cannot be handled natively by a static data entry.

2. General Methodology & Technical Stack

To bridge the identified data gap without adding qualitative text descriptions, we executed a structured, data-driven workflow:

Step 1: Ontology Module Analysis We explored the ArCo documentation, isolating the Denotative Description module (for physical tracking and dimension metrics) and the Context Description module (for subject and authorship attributions).
Step 2: Baseline SPARQL Auditing We executed programmatic lookups targeting the public endpoint to catalog missing relationships and verify target literals.
Step 3: Strict Prompt Engineering We deployed system rules, formatting inputs, and sequence constraints to force LLMs to output clean graph structures, eliminating standard conversational language.
Step 4: Multi-Model Benchmarking We ran comparative generation tasks across different architectures to evaluate schema validation errors before applying the new triples.

3. SPARQL Query Auditing Engine

To evaluate the knowledge base, we designed an audit query using all seven mandatory operational keywords: OPTIONAL, DISTINCT, UNION, FILTER, REGEX, LIMIT, and ORDER BY.

Mandatory Verification Query (Executed Against ArCo Network)

PREFIX arco: <https://w3id.org/arco/ontology/arco/>
PREFIX core: <https://w3id.org/arco/ontology/core/>
PREFIX a-cd: <https://w3id.org/arco/ontology/context-description/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT DISTINCT ?culturalProperty ?label ?author ?subjectLabel
WHERE {
  {
    ?culturalProperty a arco:HistoricOrArtisticProperty .
    ?culturalProperty rdfs:label ?label .
    FILTER(REGEX(?label, "Primavera", "i"))
  }
  UNION
  {
    ?culturalProperty a arco:CulturalProperty .
    ?culturalProperty rdfs:label ?label .
    FILTER(REGEX(?label, "Botticelli", "i"))
  }
  
  OPTIONAL {
    ?culturalProperty a-cd:hasAuthorshipAttribution ?authorRel .
    ?authorRel a-cd:hasAuthor ?author .
  }
  
  OPTIONAL {
    ?culturalProperty a-cd:hasSubject ?subjectNode .
    ?subjectNode rdfs:label ?subjectLabel .
  }
}
ORDER BY DESC(?culturalProperty)
LIMIT 50
// Audit Ledger Output:
• Returned Array: 1 Target Instance found (ex:Primavera_Uffizi).
• Structural Issue Confirmed: The a-cd:hasSubject parameter maps exclusively to the broad concept literal "Mythological Allegory". The individual sub-components representing the nine characters are completely missing from the official graph.

4. LLM Prompt Engineering & RDF Generation

We targeted the data gap using three prompting techniques, instructing the models to bypass conversational commentary and output data-ready triples directly.

Technique 1: Zero-Shot System Constraints
Isolate the core characters into independent component nodes. Strip out all aesthetic interpretations. Output only valid Turtle syntax using the ArCo framework.
Technique 2: Few-Shot Structural Alignment
[Input] Canvas: Pallas | Component: Centaur -> [Output] ex:Artwork core:hasPart ex:Node_Centaur.
[Input] Canvas: Primavera | Component: Mercury -> [Output] ex:Primavera_Artwork core:hasPart ex:Node_Mercury.
Technique 3: Chain-of-Thought (CoT) Spatial Extraction
1. Calculate boundary limits on a normalized 100x100 grid from right to left.
2. Establish separate URI nodes for overlapping actors. Map properties to ArCo documentation rules.

6. Technical Challenges, Mitigations & Conclusions

Challenge 1: Spatial Merging Errors

Characters like the Three Graces share highly integrated, overlapping visual space, making simple rectangular bounding boxes ineffective for data isolation. Mitigation: Evaluated geometry boundaries were mapped inside structured text records under a-dd:technicalCharacteristicNote attributes to maintain localized reference strings without adding external schema clutter.

Challenge 2: Representing Sequential Metamorphosis

Standard RDF structures model static assets efficiently but fail to natively handle active narrative transitions, such as Chloris transforming into Flora under Zephyrus's touch. Mitigation: We extended our local schema tracking using situational wrappers (core:Situation), creating independent chronological states to accurately model the change.

Project Strategic Conclusions

By systematically filtering away conversational text, we successfully audited and enriched the semantic data model of Sandro Botticelli's masterpiece. This project demonstrates that combining automated SPARQL verification queries with structured LLM prompt flows can successfully modernize legacy cultural collections, transforming classical fine arts metadata into highly usable, machine-readable graphs.
